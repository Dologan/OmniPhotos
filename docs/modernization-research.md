## Preserve the OmniPhotos baseline

OmniPhotos uses panoramas captured along an approximately circular camera trajectory. Proxy geometry and optical flow between neighboring frames help interpolate viewpoints and create translational parallax. A panorama taken while rotating about a stationary optical center provides little baseline for estimating depth. A circular trajectory also leaves some surfaces hidden, especially when the viewer moves away from the ring. Keep the same input frames, poses, proxy and renderer when comparing a new flow estimator. [OmniPhotos, Bertel et al., SIGGRAPH Asia 2020](https://doi.org/10.1145/3417770)

For the Insta360 ONE RS 1-Inch 360 Edition, retain the original dual-lens media and export a stitched **2:1 equirectangular** master from Insta360 Studio. Record export settings, timing and stabilization choices. Use consistent exposure and white balance where feasible. Walk a slow loop at roughly constant height. Check that a heading or stabilization change can be accounted for when registering camera poses. Inspect close railings, moving subjects and objects crossing the stitch. A stitched panorama approximates a central camera, and the dual-lens separation can leave near-field stitching errors even when scene depth is correct. Preserve the full-resolution export for comparisons. [Insta360 ONE RS 1-Inch 360 Edition](https://www.insta360.com/product/insta360-oners/1inch-360)

## What changed after the review

The import path checks for 2:1 panoramas and preserves source-frame indices through extraction and projection. The new profile estimates poses from one perspective crop per panorama and checks connected-model coverage before cache generation. DIS remains the flow baseline. The setup guide recommends a seated Quest Link check and records the paired tests required before adopting a new flow estimator, geometry prior or representation.

Sections 3.2 and 6 of the paper clarify two boundaries for those comparisons. The authors used DIS and FlowNet2 and evaluated a scene-adaptive proxy fitted to a sparse reconstruction. The validated modernization profile uses PyCOLMAP and DIS with the optional adaptive proxy fitting disabled. Compare against a separate adaptive-proxy run when aiming to reproduce the paper's visual results. Section 6.1 describes the original experience as 5-DoF: arbitrary head rotation and translation in the capture plane. Validate horizontal translation within the capture ring and score vertical motion separately as a limitation. [OmniPhotos paper, sections 3.2, 4, and 6](https://richardt.name/publications/omniphotos/OmniPhotos-BertelEtAl-SIGAsia2020-paper.pdf)

## Test candidate methods independently

| Area | Candidate and adoption criterion |
| --- | --- |
| Camera trajectory | Compare a maintained spherical SLAM implementation such as stella_vslam with the existing OpenVSLAM trajectories. Verify timestamp and image identity, world-to-camera conventions, loop closure, metric scale and camera coverage independently of downstream rendering. The implemented PyCOLMAP profile uses one perspective crop per panorama and serves as the comparison for a future spherical SLAM adapter. With multiple crops per panorama, model the known relative orientations and shared camera center. Crops from the same panorama provide additional views of the scene at that center. [stella_vslam](https://github.com/stella-cv/stella_vslam) · [COLMAP](https://github.com/colmap/colmap) |
| Correspondence | Compare DIS, RAFT and SEA-RAFT on the RTX 4080. Avoid running high-resolution all-pairs correlation over an entire panorama. Evaluate overlapping perspective faces or seam-aware tiles. Reproject matched endpoints as rays before combining correspondences, wrap longitude and retain a validity mask. Measure forward/backward angular cycle error and retained coverage, and repeat after shifting the panorama seam. Preserve the Viewer’s existing flow direction, scaling and file conventions when testing a drop-in replacement. [RAFT, ECCV 2020](https://arxiv.org/abs/2003.12039) · [SEA-RAFT, ECCV 2024](https://arxiv.org/abs/2405.14793) |
| Geometry | Try Depth Anything V2 as a relative-depth prior. Fit its scale against shared multi-view geometry using overlapping perspective views and check optical-axis depth versus ray distance and depth versus inverse depth. Evaluate occlusion boundaries and temporal scale drift. Keep the prior optional until it improves held-out views. [Depth Anything V2, 2024](https://arxiv.org/abs/2406.09414) |
| Separate reconstruction baseline | Try 3D Gaussian Splatting on a well-covered static scene, with capture-ring and off-ring test poses. Outward-facing capture gives uneven scene coverage, and crops of a single panorama share the same approximate projection center. Evaluate memory, sustained stereo rendering time and disocclusion artifacts on the target before using splats in the production path. [3D Gaussian Splatting, SIGGRAPH 2023](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/) |

## Quality gates

1. Use fixed scenes with near railings, thin structures, textureless walls, foliage and distant detail. Hold out a set of capture-ring frames with temporal buffers and a second short, registered capture off the ring. Use the latter for translation and disocclusion checks.
2. Compare identical angular viewports with the same exposure and color transform. Report edge doubling, seam discontinuities, unobserved coverage and temporal flicker separately. If computing full-panorama PSNR, weight mean squared error by the cosine of latitude. Measure LPIPS on perspective views sampled approximately uniformly by solid angle. Report masked and unmasked results. [LPIPS, CVPR 2018](https://arxiv.org/abs/1801.03924)
3. Change capture/export, flow, geometry prior and renderer compression one at a time, then evaluate the combined candidate. Record preprocessing time, peak host and GPU memory, registration coverage, and the output quality measures for each.
4. Check stereo translation, controller binding, recentering and sustained rendering on Quest 3. Record dropped frames and p50, p95 and p99 CPU/GPU frame times. The full display interval is 13.89 ms at 72 Hz and 11.11 ms at 90 Hz, with part of that budget reserved for the runtime. Test Link before Air Link to isolate the rendering path from wireless variability.
